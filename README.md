# Orbit Planner

Веб-сервис автономного планирования работы спутниковой группировки.
КосмоХакатон 2026, кейс «Автономное управление спутниковой группировкой».

Оператор загружает сценарий, выбирает цель управления (приоритетное обслуживание или
коммерческая отдача), запускает расчёт по шагам, вводит сообщения (новые задания,
недоступность аппаратов, отмена сеансов), сравнивает ветви из одного состояния и
выгружает воспроизводимый результат.

## Запуск

Требования: Python 3.10+, Node.js 20+.

```bash
make install     # venv + npm install
make dev-api     # API на :8000
make dev-ui      # UI на :5173 (проксирует /api на :8000)
make test        # pytest
```

Один процесс (UI собран и раздаётся FastAPI): `make serve` → http://localhost:8000.
Docker: `docker build -t orbit-planner . && docker run -p 8000:8000 orbit-planner`.

## Структура

```
model/            расчётная библиотека организаторов (без изменений)
data/             сценарии P01–P04
examples/         пример сообщений events_demo.json
backend/app/
  main.py         HTTP API
  runs.py         независимые запуски, ветвление, история смены цели, run_metadata
  scenarios.py    загрузка сценариев и изменение начальных условий
  planners/       планировщики; регистрация в planners/__init__.py
  analysis.py     объяснения: статус заданий, доказуемая невыполнимость
backend/tests/    воспроизводимость, атомарность событий, независимость ветвей
frontend/         React + Vite, экран оператора
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | сценарии, цели, планировщики |
| POST | `/api/runs` | новый запуск: `scenario_id` или `scenario`, `goal`, `planner`, `params`, `overrides` |
| GET | `/api/runs/{id}` | шаг, сводка, состояния аппаратов |
| POST | `/api/runs/{id}/advance` | `{"steps": n}`, `{"until_step": k}` или `{}` до конца |
| POST | `/api/runs/{id}/events` | одно сообщение; некорректное отклоняется, состояние не меняется |
| POST | `/api/runs/{id}/goal` | смена цели на границе шага (пишется в историю) |
| POST | `/api/runs/{id}/fork` | ветвь из текущего состояния с другой целью/планировщиком |
| GET | `/api/runs/{id}/jobs` | задания с прогрессом и статусом |
| GET | `/api/runs/{id}/trace` | журнал шагов (`?satellite_id=`) |
| GET | `/api/runs/{id}/result` | выгрузка `cosmo-B-ops-result-1.0` |

`overrides`: `initial_soc` `{sid: pct}`, `solar_factor`, `job_priority` `{job_id: p}`,
`failures` `[{satellite_id, start_step, end_step}]`. Изменённые условия — новый сценарий
с нулевого шага.

## Воспроизведение выгрузки

```bash
python model/operations.py --result result.json --output replay.json
```

## Планировщики

| Имя | Описание |
|---|---|
| `greedy-edf` | простое правило для сравнения: ближайший срок (цель «выручка») или приоритет → срок (цель «приоритет»); калибровка за шаг до истечения; сами соблюдаем лимит downlink и одного исполнителя на задание |

Новый планировщик — класс с `name`, `version`, `params()`, `plan(session, goal)`,
добавленный в `PLANNERS`. Планировщик видит только текущее состояние и уже полученные
сообщения.
